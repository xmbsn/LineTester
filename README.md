# 机房线路稳定性测试工具 v4

主动探测 + 被动应答一体的机房间线路测试工具。每个机房跑一份程序，
双方互相探测对方的监听端口，输出实时统计与 CSV 历史日志。

## 配置方式

所有运行参数统一由**程序目录**（EXE 所在目录）下的 `appsettings.json` 管理。
界面只是配置的可视化入口。

| 操作 | 行为 |
|---|---|
| 程序启动 | 读取程序目录下的 `appsettings.json`，填入界面 |
| **保存配置** | 把界面参数写回 `appsettings.json`（原子写入，先写临时文件再替换） |
| **启动测试** | 先把界面参数写回文件，再按该配置开始监听与探测；同时清空界面统计、重新开始统计 |
| **清除** | 只清空界面上的统计数据、异常记录与明细，并从当前时刻重新开始统计；**运行中可反复点击**，不影响监听与探测，也不删除历史日志 |
| **停止测试** | 停止监听与探测，界面保留已统计到的数据。停止时正在进行的探测会被取消且不计入统计；停止前已完成测量、尚未刷新的那一轮结果属于真实数据，仍会保留 |
| **协议勾选（TCP / UDP）** | 只有勾选的协议才会发出探测包，**取消勾选立即生效**（无需重启测试），该协议随即停止发包；不会删除已统计到的数据 |
| **链路配置页** | 在界面里直接新增 / 复制 / 删除链路并逐行校验，不必再手改 appsettings.json；**改动运行中即时生效**（协议勾选立刻，其余约 1 秒防抖） |

### 链路配置（链路编辑器）

「链路配置」页就是 `Links` 的可视化编辑入口，双击单元格即可编辑「名称 / 主机·IP / 端口 / TCP / UDP」：

| 功能 | 说明 |
|---|---|
| **新增链路** | 未选中行时插入一条空链路；选中某行时以它为模板新增（名称自动加 `-副本`），并自动进入编辑状态 |
| **复制所选** | 把选中的（可多选）链路复制成新行 |
| **删除所选** | 删除前**必须确认**，确认框里会显示链路名与目标；已统计的数据与历史日志不受影响。**注册链路会被拦下**并提示去注册中心操作（见「多机房自动互测」） |
| **撤销删除** | 恢复最近一次删除的链路（连原位置一起恢复），按钮上会显示可恢复的条数 |

「**来源**」列区分 `本地` 与 `注册中心`：注册链路由注册中心同步维护，**名称/主机/端口只读**（本地改了也会被下一个同步周期覆盖），
只保留一个本地开关——把 TCP 与 UDP 都取消勾选即「本地已停测」（同步不会覆盖这个意图）。

**校验**：每一行都实时校验，非法行整行标红并在「校验」列写明原因，页脚摘要同时汇总。

- 单行规则：名称必填、主机/IP 必填、端口为 1~65535 的整数。
  **TCP 与 UDP 都未勾选也是合法的**——表示这条链路不主动探测（见下）。
- 跨行规则：同一目标（名称+主机+端口）的同一**已启用**协议重复配置会被判为重复，并提示"与第 N 行重复"。
- 校验规则与配置文件校验**共用同一份实现**（`ConfigManager.ValidateLink`），不会出现界面放行、文件报错的情况。
- **校验未通过时，「保存配置」与「启动测试」都会被拒绝**，并自动跳到「链路配置」页指出问题行；生效中的链路配置不会被改写。
- 端口用文本承载，所以填了 `abc` 也会被标红提示，而不是被绑定悄悄吞掉、保存时写回旧端口。

#### 纯服务端节点 / 单条链路停测

- **整台程序当纯服务端**：`Links` 留空，或所有链路都不勾协议。程序只监听 `ListenPort`
  并应答对方的探测，自己不主动发包。状态栏会提示「当前没有生效的探测…只会监听应答」，
  链路配置页摘要会提示「N 条不主动探测（TCP/UDP 都未勾选，对端可能是纯服务端）」。
- **只停测某一条链路**：把该行的 TCP 与 UDP 都取消勾选即可——名称、主机、端口全部保留，
  以后想恢复直接勾回来，不必删掉再重建。
  「生效（实际发包）」列会显示 `不发包`；该链路不会出现在实时统计里，也不会写日志。
- 重复检测只针对**已启用**的协议，所以停测的链路不会与别的链路判成重复。

**防误删**：删除必须确认（默认按钮是"否"）、删除最后一条链路时额外警告"之后只会监听应答不再发包"、删除后还能一键撤销；另外 `Del` 键不会删除行，只能通过按钮删除（按钮才带确认）。

**何时生效**：链路改动**运行中即时生效**——协议勾选（TCP/UDP）立刻生效，主机/端口/名称等改动约 1 秒后生效
（防抖：端口是一格一格敲进去的，逐字符生效会真的往 9 端口发包）。未运行时改动会在下次「启动测试」时生效。
由注册中心同步下来的链路同样**不需重启**：新节点自动加入统计，中心删掉的当场消失。

### 协议勾选

界面上的 **TCP / UDP 勾选框** 是全局**总开关**，与每条链路自身的 `Tcp`/`Udp` 是**“与”关系**（取交集）：

> **只有两边都勾，才会真正发该协议的探测包。全局开关只能收紧，不能放宽。**

| 全局 TCP | 链路 Tcp | 实际是否发 TCP |
|---|---|---|
| ✅ | ✅ | **发** |
| ✅ | ❌ | 不发（链路自己关掉了） |
| ❌ | ✅ | **不发**（被总开关压住，链路怎么勾都没用） |
| ❌ | ❌ | 不发 |

- 冲突时**以更严格的一方为准**：总开关取消勾选的协议，无论链路怎么配都不会发。
- 「链路配置」页有一列 **「生效（实际发包）」** 直接显示每一行最终会发什么（`TCP + UDP` / `TCP` / `UDP` / `不发包`），不用自己推。
- 页脚摘要在发生"压住"时会点名：`全局未勾选，已压住：机房B 的 UDP（总开关只能收紧）`。
- 探测循环**每一轮都重新读取总开关**，所以运行中取消勾选会在下一轮立刻停止发送该协议的包；
  链路级的 TCP/UDP 勾选同样**立刻生效**（最多允许切换那一刻已在途的 1 个包）。
- 状态栏实时显示总开关状态（`TCP + UDP` / `仅 TCP` / `仅 UDP` / `无（只监听不应答探测）`）与「生效探测 N 路」（已按交集计算）。
- 两个总开关都不勾 = 纯被动应答节点：仍然监听端口并回包，只是自己不主动探测。
- 勾选状态保存在 `appsettings.json` 的 `EnableTcp` / `EnableUdp`；链路级状态在各自的 `Tcp` / `Udp`。

> 程序**不会**在运行期间自动重新读取配置文件。若配置文件在运行中被其它程序
> （记事本、脚本等）修改，点击“保存配置/启动测试”时会提示选择：
> **重新加载文件** / **用界面值覆盖文件** / **取消**，不会静默覆盖你的修改。

### 仓库根目录的 appsettings.json 是模板

编译与发布会把它复制到输出目录 / 发布目录（`PreserveNewest`）。
现场部署时请直接编辑 **EXE 同目录** 的那一份；模板只在副本较旧时才被覆盖。

## appsettings.json

```json
{
  "ListenPort": 8800,
  "IntervalMs": 1000,
  "TimeoutMs": 1000,
  "WarningRttMs": 300,
  "StatWindowMinutes": 60,
  "LossWarnPercent": 1.0,
  "ConsecutiveLossWarn": 3,
  "EnableTcp": true,
  "EnableUdp": true,
  "Links": [
    {
      "Name": "机房B",
      "Host": "203.0.113.20",
      "Port": 50001,
      "Tcp": true,
      "Udp": true
    }
  ],
  "Registrar": {
    "Enabled": false,
    "NodeName": "",
    "PublicHost": "",
    "PublicPort": 0,
    "CenterHost": "",
    "CenterPort": 0
  }
}
```

支持 `//` 注释与尾逗号，中文不会被转义成 `\uXXXX`，可以直接用记事本编辑。

> `Registrar` 段**默认不启用**：不勾选「参与注册同步」时，行为与升级前完全一致（一个注册报文都不发）。

### 参数说明

| 参数 | 说明 |
|---|---|
| ListenPort | 本机 TCP/UDP 监听端口（双栈：IPv4 与 IPv6 同时应答） |
| IntervalMs | 主动测试间隔，最小 50（按轮次起点计时，探测耗时不会让间隔越跑越长） |
| TimeoutMs | 一次探测等待对端回复的最大时间；超过即判定超时/丢包 |
| WarningRttMs | 窗口内平均 RTT 达到该值记为“高延迟” |
| StatWindowMinutes | 实时统计的滑动时间窗口 |
| LossWarnPercent | 窗口内丢包率达到该百分比才判定“有丢包”（默认 1%，避免历史上一两次丢包长期报警） |
| ConsecutiveLossWarn | 连续丢包达到该次数判定“中断” |
| EnableTcp / EnableUdp / EnableIcmp | 全局协议开关（对应界面上的 TCP / UDP / ICMP 勾选框）：只有为 `true` 的协议才会发出探测包。ICMP 默认关闭，见「ICMP（ping）探测」 |
| Links | 要测试的远端机房列表；`Tcp` / `Udp` / `Icmp` 可分别开关（与全局开关是“与”关系）；**三者都为 `false` 表示该链路不主动探测**（纯服务端 / 临时停测） |
| Links[].Source | `manual`（本地手工，默认）/ `registry`（由注册中心同步维护）。**注册链路不要手工改**，改了下一个同步周期会被覆盖 |
| Links[].LocalDisabled | 注册链路的“本地停测”意图：界面里把该行 TCP 与 UDP 都取消勾选即置位，**同步不会覆盖它** |
| Links[].LocalTcpOff / LocalUdpOff / LocalIcmpOff | 注册链路的**单协议**本地意图（例如只想测 UDP）：界面里取消勾选该协议即置位，**同步不会覆盖它**——以前单独取消勾选会在下一次同步被改回去 |
| Registrar | 多机房自动互测（注册中心）配置，见下一节 |
| Isp | 运营商信息查询（`Enabled` / `Endpoint` / `CacheDays` / `TimeoutMs`）。默认启用；关掉后不发送任何 IP，见「运营商信息与跨运营商判定」 |
| Registrar.PublicHosts | 本端**其余**外网地址（不含主地址；端口与主地址共用）。同一机房多个出口 IP 时填这里 → 其他节点为每个地址各生成一条链路 |

### 运营商信息与「是否跨运营商」判定

「链路实时统计」表里有三列与运营商相关：**目标运营商**、**本端运营商**、以及带状态灯的 **跨网**。

| 灯色 | 含义 |
|---|---|
| 🟢 绿 | 同运营商（如上海电信 ↔ 广东电信）/ 同一张网（同 AS） |
| 🔴 红 | 跨运营商（如电信 → 联通）/ 跨网（电信 → 阿里云、阿里云 → 腾讯云） |
| ⚪ 灰 | 数据不足，**不判定**（本端出口 IP 还没拿到、目标是内网地址、查询失败/被限流）——宁可灰灯也不误报红 |

判定规则（数据来自 ip-api 的 `isp` / `org` / `as`）：

1. 先按**运营商大类**比：电信 / 联通 / 移动 / 广电 / 教育网。**同大类 = 绿**（同一家运营商的省网之间 AS 不同，也算同运营商）。
2. 一侧是**云厂商/IDC 或海外**、或某侧大类识别不出时，退化为**比 AS 号**：同 AS = 同一张网（绿），不同 = 红。
3. 查不到、字段自相矛盾、内网地址 → **灰灯**；鼠标悬停在「跨网」列上可看两侧的 ISP 与 AS 原文，人工判断。

实测踩过的坑（决定了上面的规则）：
- 联通的老网通资源（如 `221.5.88.88`）isp 写的是 `CNC Group CHINA169 …`，**既没有 "unicom" 也没有“联通”** → 只按关键词匹配会误判成“未知”；
- `114.114.114.114` 的 `isp` 说联通、`as` 说电信（**同一份返回里互相矛盾**）→ 只能给未知，不能硬猜；
- 阿里/腾讯/百度是**云厂商自己的 AS**（AS37963 / AS132203 / AS38365），归到“电信/联通/移动”里是错的。

**联网与隐私**（重要）：

- 需要把 IP 发给第三方 [ip-api.com](https://ip-api.com)。**免费接口只支持 HTTP 明文（无 HTTPS），且官方声明不允许商用** —— 是否启用请按你们的合规要求决定。
- 参数区有开关「显示运营商信息并判断是否跨运营商」，**取消勾选后程序一个字节都不会往外发**（统计表该列显示“未启用”）。
- **只查公网地址**：内网/回环/CGNAT 等本地就能判定，不占用免费额度。
- 免费额度 **15 次/分钟**，因此实现为：**批量查询（一次最多 100 个 IP）+ 结果落盘缓存**（`ip-isp-cache.json`，默认 30 天）+ 读取 `X-Rl`/`X-Ttl` 响应头，**被限流就停手**（持续超限会被封 1 小时）。
- **本端运营商**用的是探测报文里回显的“对端看到的本端源地址”—— 每条链路各自真实的出口 IP，不需要额外去问“我的 IP 是多少”。它要在**首次探测成功之后**才有值（此前显示“尚无对端回显”）。
- 目标是域名时先解析成 IP 再查询（解析结果一起缓存）；一个域名解析出多个 IP 时，这里用的是解析到的第一个。

#### 运营商信息没显示？按这个顺序看

统计表**先看测试结果**（平均RTT、P50/P95/P99、发送/丢包、丢包率、连续丢包、状态、失败原因），目标运营商、跨网、本端出口（运营商） **排在最后三列**。跨网 列鼠标悬停能看到两侧的 ISP/AS 原文；表正下方还有一行**运营商查询状态**直接写着原因。

> 列宽按默认窗口宽度算过（合计约 1250px，可用约 1300px），**不需要横向滚动**——之前正是因为列太多把运营商列挤出了可视区，看起来像没有这个功能。自检里有断言守着这件事。

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 整列看不到 | 窗口被手动缩小过，或系统 DPI 缩放较大 | 默认宽度下列宽合计约 1250px、一屏放得下；拉宽/最大化窗口即可，也可拖表头调整列宽 |
| 「目标运营商」写着**内网地址** | 目标是内网 IP（10./172.16-31./192.168./回环）——内网**没有**运营商信息，这是本地判定、不联网 | 若这条链路走专线/VPN 的内网地址，就没有“跨运营商”可言，属正常 |
| 「跨网」写着**未知**（灰灯） | 两侧有一侧没数据：本端出口还没学到，或目标没查到 | 鼠标悬停「跨网」看明细，里面会写明缺哪一侧 |
| 本端出口显示 **尚无对端回显** | 该协议从未探测成功过（例如机房只映射了 UDP），拿不到本端出口 IP | 已做回退：自动复用**同链路其它协议**学到的出口 IP（提示框会注明来源）；两个协议都没成功就只能等探测成功 |
| 写着**查询中…** | 刚启动 | 等几秒；若一直这样，看状态行里有没有失败原因 |
| 写着**查询失败** | 这台机器访问不了 ip-api（防火墙/代理/上网门户劫持） | 用下面两行命令在该机器上确认；不通时关掉开关即可（不影响测试） |
| 写着**被限流…** | 触发了免费额度（15 次/分钟）；程序会按 `X-Ttl` 自动等，不会硬撞 | 等几十秒自动恢复；缓存生效后不会再频繁查询 |
| 写着**未启用** | 参数区的开关没勾 | 勾上「显示运营商信息并判断是否跨运营商」 |
| 结果明显不对（刚换过网络/改过目标/以前显示过未知） | 本地缓存（默认 30 天）里的旧结论 | 点参数区的 **「重查」**：清空缓存并立刻重查 |
| 停止测试后运营商列不显示了 | 这是曾经的 bug：停止时把查询服务销毁了 | 已修：停止只是不再发包，运营商信息继续显示（缓存也保留，再启动立刻可见） |

排查过程中踩到过**三个**坑（都已修，且有回归断言守住）：

1. ip-api 返回的地址字段名叫 `query`，本地模型叫 `Ip`——直接反序列化会得到“每条记录地址为空”，
   于是所有地址都被判成“无数据”，界面上的运营商永远显示未知。**假抓取器测试不经过 JSON，测不出来**；
   现在解析单独抽成函数，并用真实报文做断言。
2. 响应不是合法 JSON 时（被代理/上网门户换成网页）原来会抛异常；现在按“查询失败”处理并把原因显示出来，
   **不会**把它记成“每个地址都没数据”缓存住。
3. **修好 ① 之后界面还是显示未知**——因为 ① 写进缓存的“无数据”记录有 30 天 TTL，
   程序启动先读缓存、读到坏数据照旧显示未知（“改了还是没改好”就是这么来的）。现在：
   缓存带 **schema 版本**（形状/版本不符整份丢弃并自动重查）、坏记录单条丢弃、
   服务端没返回的地址只安排重试而**不写进缓存**，参数区还有 **「重查」** 按钮一键清空重来。

> 统计表里的**「对端看到的本端地址」列已删除**：它和「本端出口（运营商）」是同一个信息，
> 现在合并成一格显示（`IP:端口 · 运营商`），不再重复占位。

### RTT 曲线（把会话画成图）

「链路实时统计」页最左侧新增一列**「曲线」勾选框**：勾一条或多条，切到 **「RTT 曲线」** 标签页就能把它们的延迟画成曲线。**勾选只决定"显不显示"——所有链路的数据从启动测试起就一直都在记**，所以后来才勾的链路也能看到勾选之前的整段曲线。曲线名是**链路名称 + 协议名称**（例如 `东莞机房#2 · UDP`），图例颜色与曲线颜色一致。

| 项 | 说明 |
|---|---|
| 横轴 | **整个会话**（从点「启动测试」/「清除」那一刻到当前），不是滚动窗口——先看整段什么样，再缩进去看细节 |
| 纵轴 | RTT 毫秒，**上界只跟当前可见数据的最大值走**（自适应，不拿阈值/固定值当上界）——数据只有 20ms 时刻度就是 0~25ms，曲线铺满整幅图；本机回环那种零点几毫秒也照样自适应（刻度标签会自动多带小数位） |
| 阈值线 | `WarningRttMs`（默认 300ms）落在刻度内时画橙色虚线并标注；**超出刻度时不画线**，只在右下角标一句「峰值未到阈值 300ms」——不为了画阈值线而把数据压到图底 |
| 缩放 | **滚轮缩放，以鼠标位置为锚点**（盯着看的那一段不会跑掉）；最小缩到 2 秒 |
| 平移 | **左键拖拽**左右平移，不会拖出会话范围 |
| 回到全程 | **双击图内**，或点工具条的「全览」按钮；缩放过时按钮才可用，旁边一直写着"我现在看的是哪一段" |
| 悬停 | 竖线**吸附到最近的采样时刻**，提示框列出**同一时刻所有曲线**的取值（丢包显示"丢包"），时刻精确到毫秒、可与 CSV 日志对齐；该时刻每条曲线的取值点会在线上标出来 |
| 丢包 | 曲线在该处**断开**，下方画一根淡红竖条 + 断口处一个**红色空心点**（高度取上一次成功的 RTT，用于判断丢包落在哪一段） |
| 图例 | 点图例可**隐藏/显示**某条曲线（隐藏后文字加删除线）；取消勾选「曲线」列则整条曲线从图上撤掉 |
| 多条链路太多 | 颜色用的是色盲友好的固定色板（Okabe-Ito + 补充色），相邻色可区分；图例按勾选顺序排，颜色不会乱跳 |
| 长会话会不会糊 | 不会：横轴按**像素列聚合**，每列画该时段的最小/最大包络 + 均值折线，**数据一条不丢**（不做隔点抽样，尖刺不会被抽掉）；一屏放不下时也不会糊成一团 |
| 勾选与记录 | **记录与勾选无关**：启动测试后所有链路的数据一直在记（含从没勾过的），勾选只是把它显示出来。所以"晚勾选"也能看到勾选之前的整段；取消勾选不清历史、重新勾上还是完整一条 |
| 曲线数据存哪 | 只存在内存里（属于当前会话，不落盘）；「清除」会清空曲线，「实时RTT明细」那张表只留最后 2000 条、曲线不受它限制 |

> 曲线页是**自绘**的（本项目零 NuGet 依赖，用不了 LiveCharts/OxyPlot 这类库）。
> 没有视觉模型可以"看一眼"，所以曲线的正确性靠三类断言守着：历史缓冲与纯计算（刻度/聚合/缩放锚点/悬停吸附）、
> **像素级渲染断言**（按配色数像素，证明曲线/刻度/阈值线/丢包标记真的画到了画面上）、真实窗口端到端。
> 好看不好看只能人看：`dotnet run --project .\tests\LineTester.Tests -c Release -- --render-ui .\.ui-preview\ui.png` 会输出各页截图（`ui_1.png` 就是曲线页）。

### ICMP（ping）探测

除了 TCP / UDP，还可以用 **ICMP ping** 探测链路——特点是**不要求对端运行本工具**（回包由对端操作系统应答），适合"对端没装程序 / 只想确认主机在线"的场合。

怎么开：

1. 「参数设置」里勾上 **ICMP** 总开关（默认**关闭**）；
2. 「链路配置」页把该行的 **ICMP** 列勾上（与 TCP/UDP 同一套「全局 ∩ 本行」规则，总开关只能收紧）。

| 特性 | 说明 |
|---|---|
| 端口 | **ICMP 没有端口**：ping 的是主机，链路里的端口对它无意义 |
| 统计 | 延迟（当前 / 平均 / P50 / P95 / P99）与丢包率走**和 TCP/UDP 完全相同的一套统计口径**，界面里单独一行（协议列显示 `ICMP`），可以和 TCP/UDP 直接横向对比 |
| 对端要求 | **不需要**对端运行本工具（回包由操作系统内核产生） |
| RTT 精度 | **1 毫秒**（Windows `IcmpSendEcho` 的限制），不像 TCP/UDP 是微秒级 |
| 「对端看到的本端地址」 | ICMP 拿不到（内核不会替我们回显），该列显示 `-`；本端运营商由同链路其它协议的结果补齐 |
| 权限 | 用系统 ping 接口，**不需要管理员权限**、不使用原始套接字 |
| 失败原因 | 对端禁 ping 与线路不通在网络层都表现为"无响应" → ICMP 超时显示 **"无响应（超时；对端可能禁 ping 或线路不通）"** |
| 防火墙 | Windows 默认**禁止入站 ICMP 回显**。要让别人能 ping 通本机：<br>`New-NetFirewallRule -DisplayName "LineTester ICMPv4-In" -Direction Inbound -Protocol ICMPv4 -IcmpType 8 -Action Allow` |
| IPv6 | 目前只支持 IPv4 目标（IPv6 会明确报"只支持 IPv4"） |
| 注册中心 | 「注册中心」页可勾「ICMP」（允许被 ping）。默认不勾——乱宣告会让别的节点把"对端禁 ping"当成线路故障（与「可被 TCP 探测」同理） |

排查入口（不启动程序也能复现）：

```bat
:: 连续 ping 同一个目标，逐次打印结果（看"是不是发几次就停"）
dotnet run --project .\tests\LineTester.Tests -c Release -- --icmp-loop 127.0.0.1 12 300 2000

:: 真实窗口 + 真实探测循环跑 12 秒，每秒打印各协议累计条数与三个开关的当前取值
dotnet run --project .\tests\LineTester.Tests -c Release -- --icmp-window 12
```

### 多机房自动互测（注册中心）

N 个机房两两互测需要 N×(N-1) 条链路，手工录入随 N² 增长。启用注册后，
**每个节点只填“自己 + 注册中心”**，链路自动生成/删除。协议细节见 `docs/REGISTRY-PROTOCOL.md`。

> **界面顶部会大号显示本机节点名称**（同时开多个实例、或对着多台机器的远程桌面时，一眼认出这台是哪台）。
> 名字取自「注册中心」页的 `节点名称`，**改完立刻生效**（不必先保存）；还没填时显示"未命名节点"并提示去哪儿填。
> 窗口标题也会带上它，方便在任务栏里区分多个实例。

**现场只需三步**（以三个机房 A/B/C，中心放在 A 为例；所有节点都用同一个监听端口 8800 并被机房映射到各自的公网端口）：

1. 每个节点打开「注册中心」页，勾选**参与注册同步**，填**两组地址**（最容易被填混的地方，两组说的不是同一件事）：
   - **本端**（别人怎么连到我）：`节点名称`（其他节点上自动生成的链路名）、`本端外网地址`、`本端外网端口`
     = 机房**映射到本机**的那个地址与端口（例如 `203.0.113.9:16298`）。**不是**出口源端口，也**不是**注册中心的端口。
     **同一机房有多个外网 IP 时**：把第一个填进输入框、点「添加」，再填下一个、再点「添加」；
     端口对所有地址共用。其他节点会为**每个地址各生成一条链路**（`东莞机房`、`东莞机房#2`、`东莞机房#3`），
     这样三个地址的运营商与线路质量能分别看（见「运营商信息与跨运营商判定」）。
   - **注册中心**（我怎么找到中心）：`中心地址`、`中心端口` = 中心**映射出去**的地址与端口（例如 `203.0.113.1:16298`）。
   - `预共享密钥`：各节点与中心**必须填成同一个值**（可留空，但清单会标记“无密钥”）。
   - 只想测别人、不需要被别人测的节点：取消勾选**参与网状**，这时**本端外网地址/端口可以留空**。
2. 中心的那个节点额外勾选**本机同时承担注册中心角色**；它自己的“中心地址”可填 `127.0.0.1`（本机回环），中心端口填本机监听端口。
3. 各节点点「启动测试」。默认 60 秒一次心跳、300 秒一次同步；中心侧新增/删除节点会在一个同步周期内传播到所有节点。

| 界面元素 | 说明 |
|---|---|
| 本节点 → 参与网状 | 关闭后本节点不会被分发给其他节点（别人不会测你），你仍照常测别人；此时本端外网地址/端口可留空 |
| 本节点 → 可被 TCP/UDP 探测 | “允许别人怎么测我”。机房只映射了 UDP 就关掉 TCP，否则对端会把必然失败的探测判成线路故障 |
| 状态区 | 中心连接状态、`中心看到的源地址 vs 手填外网地址`的核对、本节点分发状态（回环地址会被拦） |
| 「来源」列（链路配置页） | `本地` / `注册中心`；注册链路的名称/主机/端口**只读** |
| 中心管理表（仅中心可见） | 在线/分发/认证状态；**移除**（权威删除，会从所有子节点链路里消失）/ **恢复**；「分发」取消勾选 = 该节点立刻不分发出去，且不会被它的心跳顶回来 |

**注意**

- `本端外网地址`+`端口` **必须手工填写**（参与网状时）：出方向 NAT 的源端口与入方向映射端口通常不同，
  程序无法从“中心看到的源地址”自动推断（那只是出方向的地址）。状态区会把它和中心看到的值并列显示供核对。
  提示里会把**当前实际读到的内容**回显出来，方便发现“框其实是空的”或“混进了全角数字”。
- **回环/未指定/链路本地地址永远不会被分发**：`127.0.0.1` 会让其他节点测到自己的回环（等于假线路），因此被明确拦截并在状态区提示。
- 只想在本机停测某条注册链路：把该行 **TCP 与 UDP 都取消勾选**（“本地已停测”）；**只想测单协议**（例如只留 UDP）就取消勾选另一个协议——两种本地意图都会写回配置，**同步不会覆盖**，重启后依然保持。
- **改了注册配置（节点名 / 外网地址 / 可被探测的协议 / 密钥）后点「保存配置」，程序会自动重建同步客户端并立刻重新注册**，中心那边马上看到新值（以前必须重新点一次「启动测试」才生效）。
- 删除注册链路请在**注册中心侧**操作；本地删除会在下一个同步周期被加回来（中心仍在分发那个节点）。
- 中心侧若留着**长期离线（>7 天）**的历史节点（换过配置/退役的机器），所有子节点会一直维持到旧地址的链路——“我本地删了它、过一会儿又回来”通常就是它。在「注册中心管理」里点 **「清理长期离线」**，或按 **节点 ID 短号** 找出同一台机器的重复历史行并「移除所选」。
- 中心不可达不影响测试：继续用上次同步到的链路，状态栏提示“不可达（退避中）”，恢复后自动续上。
- 中心与本测试端共用**同一个监听端口**，靠报文前缀 `LT1|` 区分注册消息与探测包；老版本节点按原样回显，识别为“该地址不是注册中心”。

注意：`ListenPort` 没有“超时时间”。监听端口只负责接收远端测试包并立即回包；
`TimeoutMs` 用于主动发起测试的一方。

### 状态判定

| 状态 | 条件 |
|---|---|
| 中断 | 连续丢包 ≥ `ConsecutiveLossWarn` |
| 有丢包 | 窗口内丢包率 ≥ `LossWarnPercent` |
| 高延迟 | 无上述情况，但窗口内平均 RTT ≥ `WarningRttMs` |
| 正常 | 其它 |

## 指标口径

| 指标 | 含义 |
|---|---|
| 序号 / `seq` | 探测包序号，按「链路 + 协议」从 1 开始单调递增。**该序号会随探测包发出**，因此界面详单、CSV 日志与抓包（Wireshark 等）可以按序号一一对齐 |
| 探测ID / `probe_id` | 32 位十六进制 GUID，随探测包发出，用于确认回包确实属于本次探测 |
| 对端看到的源地址 / `seen_from` | 被动端回显的“它看到的本端源地址（ip:端口）”。跨公网时即本端出口公网 IP + NAT 后的源端口；对端是旧版本或该次丢包时为空 |
| RTT | 从发出首个探测字节到收齐对端回包，**不含** DNS 解析与 TCP 建连，因此 TCP 与 UDP 两行可直接比较；保留微秒精度 |
| 建连/解析(ms) / `setup_ms` | DNS/地址解析 + TCP 三次握手（UDP 仅地址解析） |
| P50 / P95 / P99 | 窗口内有效 RTT 的线性插值百分位 |

### 探测报文格式

```text
主动端发出：  序号|探测ID|v2
              例：  42|3f2a9c1d4b5e6f708192a3b4c5d6e7f8|v2

被动端回包：  序号|探测ID|v2|对端看到的本端源地址 + 换行
              例：  42|3f2a9c1d4b5e6f708192a3b4c5d6e7f8|v2|203.0.113.7:50001\n
```

- **对端看到的本端源地址**：跨公网时它就是**本端出口的公网 IP**，以及 **NAT 映射后的源端口**。
  这是唯一能确认"对方眼里的我是什么地址"的办法——排查 NAT/端口映射、多 WAN 出口、运营商 NAT 池时都用得上。
  界面（统计表 / 异常记录 / 实时明细）与 CSV（`seen_from` 列）都会逐条记录，因为**它可能每次都不同**：
  如果同一个链路在不同时间看到不同的源 IP，说明出口做了多线路负载均衡，或运营商用了 NAT 池——这本身就会造成连接类故障。
- 被动端只有在请求**带 `v2` 标记**时才追加这段；否则严格**原样回显**。
- 主动端按**前缀**校验回包（必须原样回显它发出的那段），因此串包、上一轮迟到包依然会被丢弃。
- 附加信息**不计入 RTT**：计时在收齐探测ID那一刻就停了，等待附加信息只影响后续解析（老对端最多等 120ms，不影响时延数值）。
- 序号在**发送时**分配，所以序号出现跳号 = 该次探测的结果未被记录（通常是停止/清除时被丢弃）；真正的丢包会照常记一行 `packet_loss=1`，**不会**跳号。
- 序号在程序运行期间**不会**因停止 / 清除 / 重启测试而重置，这样同一个 CSV 文件里的序号始终唯一、可对齐。

#### 版本兼容（两端可以不同时升级）

| 主动端 | 被动端 | 结果 |
|---|---|---|
| 新 | 新 | 完整功能，记录源地址 |
| 新 | 旧 | 探测**正常**，`seen_from` 为空（旧被动端只会原样回显） |
| 旧 | 新 | 探测**正常**（旧主动端不发 `v2` 标记，新被动端就严格原样回显，逐字节比对依然通过） |
| 旧 | 旧 | 与升级前完全一致 |

也就是说**任何一侧单独升级都不会让探测失败**，可以先升一端，再升另一端。

地址解析结果缓存 60 秒，且优先使用 IPv4，避免双栈主机解析到 IPv6 而对方只监听
IPv4 时出现“全量超时”的误判。

## NAT/端口映射

例如：

A 机房：
- 程序监听：9001
- 路由器公网映射：TCP/UDP 50001 → 内网 9001

B 机房：
- 程序监听：9002
- 路由器公网映射：TCP/UDP 50002 → 内网 9002

那么 A 测试 B 时，配置：

```json
{
  "Name": "机房B",
  "Host": "B公网IP",
  "Port": 50002,
  "Tcp": true,
  "Udp": true
}
```

B 程序仍然只监听自己的 `9002`。

## 日志（按天分目录）

历史日志**按天分目录**、按链路追加保存在程序目录：

```text
logs\
├─ 2026-09-20\
│  ├─ 机房B_203.0.113.20_50001.csv
│  └─ 机房C_203.0.113.30_50002.csv
├─ 2026-09-21\
│  └─ 机房B_203.0.113.20_50001.csv
└─ error.log                崩溃日志：固定路径，不按天分
```

列：`timestamp,peer_ip,peer_port,protocol,rtt_ms,packet_loss,setup_ms,seq,probe_id,seen_from,failure`

- **按天滚动**以“探测结果自身的日期”为准：跨过零点后自动写入新一天的目录；
  同一天内持续追加，每个按天文件都自带表头。
- 滚动时会把上一天的数据**落盘并关闭其文件句柄**，所以长时间无人值守运行也不会累积句柄。
- 写入在后台线程完成，不阻塞界面；文件以 `FileShare.Read` 打开，可同时用 Excel/记事本查看。
- 重启测试与“清除”都**不会**删除历史日志，工具也**不会自动清理**日志（见下）。
- 升级前产生的扁平文件（`logs\xxx.csv`）不会被移动，可自行归档。

### 清理旧日志

工具不自动删日志。按天分目录后清理很简单，例如删除 30 天前的目录：

```powershell
Get-ChildItem .\logs -Directory |
  Where-Object { $_.Name -lt (Get-Date).AddDays(-30).ToString('yyyy-MM-dd') } |
  Remove-Item -Recurse -WhatIf      # 先干跑确认，没问题再去掉 -WhatIf
```

> 想要“保留 N 天、自动删除更早的”也可以在配置里加一个 `LogRetentionDays`（默认 0 = 永不删除）；
> 因为涉及删数据，目前没有默认开启。

运行期崩溃与未处理异常会追加写入 `logs\error.log`。

## 现场排查（例如“UDP 通、TCP 不通”）

### 第一步：看“失败原因”

工具会把每次失败的原因分开（「链路实时统计」的 **失败原因** 列、异常记录/明细的 **结果** 列、CSV 的 `failure` 列）：

| `failure` | 界面文案 | 含义 | 最可能的原因 |
|---|---|---|---|
| `timeout` | 无响应（超时） | 完全没有响应 | 包**在到达监听者之前就被丢弃**：端口映射未生效、机房 ACL/安全组没放行、主机防火墙没放行、运营商封了该端口 |
| `refused` | 连接被拒绝（端口无监听） | 收到了 RST | **网络路径是通的**：映射与路由都正常，只是该端口没有程序在监听（内网映射端口填错、程序没启动、映射指到了别的机器） |
| `icmp_unreachable` | UDP 端口不可达（收到 ICMP） | 收到 ICMP 端口不可达 | **包已到达对端主机**，只是该 UDP 端口没有程序在监听 |
| `reset` | 连接被重置 | 连接被 RST 中断 | 对端程序异常退出，或中间设备（防火墙/负载均衡）主动重置 |
| `closed` | 对端提前关闭连接 | 连接建立后被对方关闭 | 该端口上的服务不是本工具（例如被别的程序占用） |
| `mismatch` | 回包内容不匹配 | 回包不是本工具回的 | 该端口上跑着别的服务 |
| `host_not_found` | 主机名解析失败 | DNS/主机名问题 | `Host` 填错或 DNS 不可用 |
| `unreachable` | 网络/主机不可达 | 路由问题 | 路由/网关问题 |
| `error` | 其他错误 | 其它异常 | 结合 `logs\error.log` 分析 |

**读法（关键）**：

- `timeout` → 问题在**到达之前**：查端口映射、ACL/安全组、主机防火墙、运营商策略。
- `refused` / `icmp_unreachable` → 问题在**到达之后**：查对端程序是否在监听、内网映射端口是否填对。

### 第二步：按顺序排除（以被动端监听 9002、公网映射 50002 为例）

1. **被动端两个协议是否都在监听**（必须同时存在）：
   ```powershell
   Get-NetTCPConnection -State Listen -LocalPort 9002
   Get-NetUDPEndpoint -LocalPort 9002
   ```
2. **被动端防火墙是否两个协议都放行**——这是“UDP 通、TCP 不通”最常见的原因（只放行了 UDP 那条）：
   ```powershell
   Get-NetFirewallRule -DisplayName "LineTester*" | Select-Object DisplayName,Enabled,Direction,Action,Protocol
   ```
   缺少 TCP 规则就补上，或直接按程序放行：
   ```powershell
   New-NetFirewallRule -DisplayName "LineTester" -Direction Inbound -Program "C:\路径\LineTester.exe" -Action Allow
   ```
3. **路由器/云安全组的 TCP 规则是否真的存在**，且**公网端口与配置里填的一致**。
   注意：本工具每条链路**只有一个 `Port`，TCP 与 UDP 共用**。
   如果机房给 TCP 与 UDP 映射了**不同的公网端口**，请拆成两条链路：
   ```json
   { "Name": "机房B-TCP", "Host": "B公网IP", "Port": 50012, "Tcp": true,  "Udp": false },
   { "Name": "机房B-UDP", "Host": "B公网IP", "Port": 50002, "Tcp": false, "Udp": true  }
   ```
   云主机还要注意：**安全组与系统防火墙是两层**，两层都要放行 TCP。
4. **从主动端直接测公网端口**（绕开本工具）：
   ```powershell
   $c=[Net.Sockets.TcpClient]::new(); $sw=[Diagnostics.Stopwatch]::StartNew()
   try { $c.Connect('B公网IP',50012); "CONNECTED in $($sw.ElapsedMilliseconds)ms" }
   catch { "$($_.Exception.InnerException.SocketErrorCode) after $($sw.ElapsedMilliseconds)ms" }
   ```
   **快失败（几百毫秒，ConnectionRefused）** = 映射通、对端没监听；
   **慢失败（约 2 秒或彻底超时）** = SYN 被丢弃 → 映射/ACL/防火墙问题。
5. **在被动端抓包**，确定 SYN 到底有没有到达（Windows 自带 `pktmon`）：
   ```powershell
   pktmon filter add -p 9002
   pktmon start -c
   # 等十几秒后
   pktmon stop
   pktmon format
   ```
   - 抓不到 SYN → 问题在被动端**之前**（路由器映射、ACL、运营商）。
   - 抓到 SYN 但没有 SYN-ACK 发出 → 被动端主机防火墙拦截，或程序没在监听。
6. **运营商/IDC 策略**：部分运营商/机房对 **80 / 443 / 8080 / 25 / 135 / 445** 等端口的**入站 TCP** 有封禁，
   而 UDP 不受限——换一个高位端口（如 50012）重试即可验证。

### 注意：要稳定区分 `refused` 与 `timeout`，超时预算要够

Windows 上“被拒绝”（RST）有时要 **约 2 秒**才返回。默认 `TimeoutMs=1000` 时，
如果 RST 回得慢，会显示成 `timeout` 而不是 `refused`。想稳定区分，把 `TimeoutMs` 调到
**3000~5000**（探测间隔足够大时没有副作用）。
