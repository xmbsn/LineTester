## 1. 目标与非目标

### 1.1 目标

机房之间是**全网格互测**（N 个机房两两互测 = N×(N-1) 条链路）。手工在每台客户端录入其他所有机房的信息工作量随 N² 增长。
本协议让每个客户端**只配置自己 + 注册中心**两项，由注册中心汇总并在各客户端自动生成链路。

| 编号 | 可验证目标 |
|---|---|
| G1 | 每台客户端只填「本端外网地址/端口 + 注册中心地址/端口 + 密钥 + 名称」，不再手填其他机房 |
| G2 | 各客户端自动获得「除自己以外的所有**可分发**节点」作为链路，协议按对端注册值生成 |
| G3 | 注册中心删除一个节点 → 其他客户端的该链路消失，**包括期间离线过的节点**（重新上线后也消失） |
| G4 | 注册中心不可达时，探测**不中断**，使用上次同步到的清单继续测试 |
| G5 | 本地手工链路永不被同步改写或删除 |
| G6 | 与未升级的老版本客户端混跑，**不产生误判丢包** |
| G7 | 回环 / 未指定 / link-local 地址**绝不进入其他节点的链路清单** |

### 1.2 非目标（YAGNI，明确不做）

- NAT 打洞、STUN/TURN、流量中继
- TLS / 证书体系 / PKI 身份（改用预共享密钥 + HMAC 保证完整性与来源）
- 多注册中心、高可用、中心间联邦
- 显式的"谁测谁"链路矩阵（部分网格用 G5 之外的方式表达：本地停测，见 §8.5）
- 协议载荷加密（载荷明文可被同链路观察者看到；如现场认为机房名敏感，后续可加可选对称加密）
- 主动推送（UDP 无连接，中心只能等客户端来拉，见 §5.1）

## 2. 术语

| 术语 | 含义 |
|---|---|
| **节点**（node） | 一个运行中的 LineTester 实例。身份 = `nodeId`（GUID，本地持久化） |
| **注册中心**（center） | 承担注册服务角色的某**一个**节点（`Registrar.ServeAsCenter=true`）。**不是独立程序**：它就是 LineTester，复用同一监听端口 |
| **清单**（registry） | 中心持有的节点集合 + 单调递增的 `revision` |
| **可分发**（distributable） | 该节点允许自己被分发给其他节点、被其他节点探测 |
| **注册来源链路** | 由同步自动生成/维护的 `Links[]` 条目（`Source=registry`） |
| **本地链路** | 人工在链路编辑器里维护的条目（`Source=manual`） |
| **探测**（probe） | 现有的 RTT/丢包测试报文（`序号\|探测ID\|v2`），与本协议共用端口 |

## 3. 拓扑与部署

```text
            ┌──────── 注册中心节点（通常只在一台开启 ServeAsCenter）
            │  ProbeServer 同一端口同时服务：探测回显 + LT1| 协议消息
            │  持有 registry.json（节点清单 + revision，原子写）
            └──▲────────▲────────▲──────  星形同步：注册 / 拉取
               │        │        │
          机房A节点  机房B节点  机房C节点     ← 每个只配「自己 + 中心」
               └────────┴────────┘
                 全网格探测（节点↔节点直连，沿用现有协议）
```

- **同步是星形，测试是全网格**：中心只负责"谁在哪"，不中转探测流量。
- 中心同时也是一个普通客户端：它也同步清单、也（在可分发时）被别人探测。
- 中心挂掉 → 只影响后续新增/删除的可见性，**不影响正在进行的测试**（G4）。

### 3.1 为什么用 UDP 而不是 TCP（实测约束）

现场实测：机房入向 **UDP 映射可用，TCP 入向不通**（见 `LineTester.md` §6）。因此：

- **本协议以 UDP 单播为唯一必需传输**；不依赖任何 TCP 入向映射。
- UDP 的请求-应答天然穿过 NAT：中心把回包发给请求的**源地址:源端口**，任何 NAT 都会放行（回包来自客户端刚发过的那个目标）。
- 代价：UDP 不可靠、不能传大包 → 协议自带**重试、请求去重、分块与位图确认**（§5.5）。
- TCP 上同一帧格式同样可用（若某天 TCP 通了，可作为大清单的加速路径），但**不是必需**，实现可后置。

## 4. 配置模型

### 4.1 新增 `Registrar` 段（`appsettings.json`）

```json
"Registrar": {
  "Enabled": true,
  "ServeAsCenter": false,
  "NodeId": "3f2a9c1d4b5e6f708192a3b4c5d6e7f8",
  "NodeName": "机房A",
  "PublicHost": "203.0.113.10",
  "PublicPort": 50001,
  "Distributable": true,
  "AdvertiseTcp": false,
  "AdvertiseUdp": true,
  "CenterHost": "203.0.113.1",
  "CenterPort": 50000,
  "Secret": "",
  "HeartbeatSeconds": 60,
  "SyncSeconds": 300,
  "RetryMs": 1000,
  "MaxRetries": 5
}
```

| 字段 | 默认 | 约束 | 说明 |
|---|---|---|---|
| `Enabled` | false | | 是否参与注册同步 |
| `ServeAsCenter` | false | | 本节点是否承担注册中心角色；开启后维护清单并提供 `registry.json` |
| `NodeId` | 首次启动生成 | 32 位 hex GUID | **节点唯一身份**；丢失会被当成新节点 |
| `NodeName` | 主机名 | 非空 | 显示名，也是生成的链路名 |
| `PublicHost` | "" | 见 §6 | **手工填写**：其他节点探测本节点用的地址 |
| `PublicPort` | 0 | 1~65535 | 手工填写：本节点对外端口（机房映射的那个） |
| `Distributable` | true | | 见 §6.2 |
| `AdvertiseTcp` / `AdvertiseUdp` | 均 true | | **对外宣告"本端可被探测的协议"**，决定其他节点生成的链路的 `Tcp`/`Udp`。默认都开；**机房只映射了 UDP 时请关掉 `AdvertiseTcp`**（否则其他节点会把 TCP 的必然失败判成线路故障）。注意这与全局协议开关 `EnableTcp/EnableUdp` **语义不同**：后者是"我主动发不发"，前者是"允许别人怎么测我" |
| `CenterHost` / `CenterPort` | "" / 0 | | 注册中心的**外网**地址与端口。中心与本机同机时可填 `127.0.0.1` |
| `Secret` | "" | 非空才启用 | 预共享密钥（HMAC），**不上线** |
| `HeartbeatSeconds` | 60 | 15~3600 | 心跳注册周期（保活，也是判活依据） |
| `SyncSeconds` | 300 | 15~3600 | 拉取变更周期；中心的 `reannounceAfter` 只允许**缩短**它 |
| `RetryMs` | 1000 | 200~10000 | 单次请求重传间隔（退避 1×/2×/4×…） |
| `MaxRetries` | 5 | 0~10 | 单次请求最大重传次数 |

### 4.2 `Links[]` 扩展（向后兼容）

```json
{ "Name": "机房B", "Host": "203.0.113.20", "Port": 50002, "Tcp": true, "Udp": true,
  "Source": "registry", "NodeId": "…", "LocalDisabled": false }
```

| 字段 | 缺省 | 说明 |
|---|---|---|
| `Source` | `"manual"` | `manual` 本地手工 / `registry` 注册来源。缺省即 manual → **旧配置无需改动** |
| `NodeId` | "" | 注册来源时记录来源节点，用于同步去重/清理 |
| `LocalDisabled` | false | 本地停测意图（§8.5）。为 true 时**无论中心下发什么协议，本链路都设为 Tcp=false、Udp=false** |

> 配置契约测试（`tests/…/Program.cs`）里"顶层键 / 链路键"的断言需要同步更新：这是**有意的契约变更**。

### 4.3 中心清单持久化 `registry.json`

```json
{
  "revision": 137,
  "nodes": [
    { "nodeId": "…", "name": "机房B", "ip": "203.0.113.20", "port": 50002,
      "tcp": true, "udp": true, "distributable": true, "centerHidden": false, "instanceId": "…",
      "firstSeenUtc": "2026-09-20T10:00:00Z", "lastSeenUtc": "2026-09-20T10:05:00Z", "online": true }
  ],
  "removedNodeIds": ["…"]
}
```

- 原子写（复用 `ConfigManager` 的写临时文件再替换 + 退避重试做法）。
- `revision` 一并持久化，保证单调（中心重启后不复用旧 rev）。
- **不存墓碑**：客户端每次拿到的是"当前可分发清单的快照"，整体替换本地的注册链路 → 删除天然传播，离线节点重新上线也会消失（见 §9）。

## 5. 协议

### 5.1 传输与端口复用

中心监听端口（= `ListenPort`，同时是探测端口）上：

```text
入站判定（顺序固定）：
  1) 报文以 "LT1|" 开头  → 本协议消息（按类型分发）
  2) 其它               → 现有探测回显路径（一行不改；含 v2 源地址附加逻辑）
```

- 不会误判：现有探测包以**数字**开头（`42|guid|v2`），老版本客户端以**十六进制 GUID** 开头。
- 一条入站报文**只会**走其中一条路径，不解析探测包的内容语义。
- 中心**绝不**回显 `LT1|` 消息（老版本会原样回显 → 由发起方识别，见 §12）。
- **非中心节点**（`ServeAsCenter=false`）收到 `REG`/`SYNC` 时回 `ERR code=unsupported`，**不要**静默丢弃——这样"把普通节点误配成中心地址"能在状态栏一眼看出，而不是等到超时。

### 5.2 帧格式

```text
单行 ASCII 文本，以 LF(\n) 结束；字段用 '|' 分隔
LT1|<TYPE>|<MAC>|<rawPayload>\n
```

- **MAC 放在帧里，而不是 payload 里**（实现期修正）。原因：`mac` 是对 `TYPE|payload` 计算的；
  若把 `mac` 字段放进 payload，就变成"签名覆盖了签名自身"——接收方按原文重算必然不一致。
  放进帧后双方对同一段原文计算，**无需任何 JSON 规范化**。
- `rawPayload` = 紧凑单行 JSON（System.Text.Json 默认不换行），UTF-8 编码。
- 单个 UDP 数据报总长 ≤ **1200 字节**（保守值：避开 1472 的 MTU 上限与常见中间设备限制）。
- 超过部分用分块（§5.5）。
- `\n` 结尾与现有"源地址附加信息以 `\n` 结束"的约定一致，便于抓包阅读。

### 5.3 消息类型

| 类型 | 方向 | 用途 |
|---|---|---|
| `REG` | 客户端 → 中心 | 注册 / 心跳 / 顺带拉取变更（幂等 upsert） |
| `SYNC` | 客户端 → 中心 | 只拉取变更、不改自身记录（供"只读镜像"或中心自身使用） |
| `ACK` | 中心 → 客户端 | 成功响应：当前 `revision` + 快照（需要时） |
| `PART` | 双向 | 分块传输的单个数据块 |
| `ACKP` | 双向 | 分块确认（位图） |
| `ERR` | 中心 → 客户端 | 失败：错误码 + 建议重试间隔 |

#### 5.3.1 `REG`

```json
{"reqId":"a1b2c3d4","nodeId":"3f2a…","name":"机房A","
 ip":"203.0.113.10","port":50001,"tcp":true,"udp":true,
 "distributable":true,"instance":"7d1e…","rev":137,
 "ts":1789000000,"nonce":"9f8e7d6c","mac":"…"}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `reqId` | 是 | 8 位 hex，本次请求唯一；中心据此去重（§5.6） |
| `nodeId` | 是 | 节点身份 |
| `name` | 是 | 显示名，1~64 字符 |
| `ip` / `port` | 是 | 本端对外地址与端口（§6 规则校验） |
| `tcp` / `udp` | 是 | **对外宣告的可被探测协议**（对应 `AdvertiseTcp`/`AdvertiseUdp`），决定别人链路的 `Tcp`/`Udp` |
| `distributable` | 是 | 是否允许被分发给其他节点 |
| `instance` | 是 | 进程启动时随机生成；中心据此识别"对端重启过" |
| `rev` | 是 | 客户端**已应用**的中心 revision；0 = 首次 |
| `ts` / `nonce` / `mac` | 是 | 认证与防重放（§5.4） |

#### 5.3.2 `ACK`

```json
{"reqId":"a1b2c3d4","rev":138,"changed":true,"reannounceAfter":180,
 "selfCheck":{"seenIp":"198.51.100.7","seenPort":41234},
 "nodes":[{"nodeId":"…","name":"机房B","ip":"203.0.113.20","port":50002,"tcp":true,"udp":true,"online":true}, …],
 "deleted":[]}
```

| 字段 | 说明 |
|---|---|
| `rev` | 中心当前 revision |
| `changed` | `false` 时表示"客户端的 rev 已是最新"，`nodes` 省略 → 响应极小（稳态 1 包） |
| `reannounceAfter` | 中心建议的下次注册间隔（秒）。**只能把客户端的间隔调短**（下限 `HeartbeatSeconds`），不能用它把客户端拖长到超过配置值，见 §8.2 |
| `selfCheck` | 中心**看到的请求源地址**，供客户端与手填的 `PublicHost:PublicPort` 对照提示（§6.3） |
| `nodes` | 当 `changed=true`：**当前全部可分发节点**的快照（含中心自身，若可分发） |
| `deleted` | 保留字段，v1 恒为空数组（快照语义下不需要，见 §9） |

#### 5.3.3 `PART` / `ACKP`

```json
PART  {"xferId":"0a1b2c3d","reqId":"a1b2c3d4","i":0,"n":3,"data":"<base64 ≤1024 字符>"}
ACKP  {"xferId":"0a1b2c3d","bitmap":"7"}      // 每 bit 一个块，bit i = 第 i 块已收到
```

- **`PART` 必须带 `reqId`**（实现期修正）：否则客户端无法把收到的分块关联到"哪个请求的应答"。

- 原始块大小 **768 字节**（base64 后恰好 1024 字符，无填充），加头部约 1100 字节 ≤ 1200。
- 位图用 hex 表示，**bit i（最低有效位为第 0 位）对应第 i 块**；块数上限 **64**（= 48 KB 原始 JSON ≈ 370 个节点）。
- 阈值关系：`rawPayload` ≤ **900 字节**时**单包**直发；超过 900 字节才分块（每块原始 768 字节）。900 留出了帧头与换行的余量。

#### 5.3.4 `ERR`

```json
{"reqId":"a1b2c3d4","code":"loopback","message":"PublicHost 是本机回环地址，不会被分发","retryAfter":0}
```

| `code` | 含义 | 客户端动作 |
|---|---|---|
| `auth` | HMAC 校验失败 / 密钥不匹配 | 状态栏报错，**指数退避**重试（不刷屏）；提示核对密钥 |
| `badrequest` | 字段缺失/格式错 | 状态栏报错，不重试（要改配置） |
| `loopback` / `unspecified` / `linklocal` | 地址不可分发（§6） | 记录提示，**仍保持心跳**（修好地址后自动恢复分发） |
| `removed` | 该 nodeId 已被中心移除（§9.1） | 状态栏提示"已被注册中心移除"，**不重试**（重试无意义，需中心侧恢复） |
| `throttled` | 超过中心限流 | 按 `retryAfter` 等待 |
| `unsupported` | 对端不是注册中心（老版本或普通节点） | 状态栏提示"该地址不是注册中心"，退避后重试 |
| `internal` | 中心内部错误 | 退避重试 |

### 5.4 认证与防重放

- `mac = HMAC-SHA256(Secret, TYPE + "|" + rawPayload)`，小写 hex；**`mac` 是帧的独立一段**（§5.2）。
  **对收到的原始文本计算**（不做 JSON 重新序列化），避免字段顺序/转义差异导致校验失败。
- 校验顺序：① 能否按帧解析 → ② `mac` → ③ `ts` 在 `|Δ| ≤ 300s` → ④ `nonce` 未见过。
- `nonce`：8 位 hex 随机。中心保留最近 **256 个** `(nodeId, nonce)`，重复即丢弃并回 `ERR auth`。
- `Secret` 为空时：中心仍接受注册，但**在清单里标记 `unauthenticated`** 并在中心界面标红（便于先跑通再上密钥）。
- **中心的所有应答都会签名**（`ACK`/`PART`/`ERR`），客户端一律校验。
- **例外：`ERR` 帧客户端不做强制验签**（实现期修正）。理由：密钥配错时报文必然验不过，
  而这正是最需要看到原因的时候——强制验签会把"密钥不一致"变成静默超时。
  `ERR` 不携带任何可信数据（只有一个错误码与说明），因此不构成信任风险。
- **确定性错误不重试**：`auth` / `badrequest` / `removed` / `unsupported` 属配置或状态问题，
  重试无意义，客户端立即置错误并等下一个周期；只有超时类错误才在本次请求内重传。
- 密钥**不上线**，只在 HMAC 输入里使用。

### 5.5 可靠性与分块

| 机制 | 规则 |
|---|---|
| 请求重传 | 发出后 `RetryMs` 内未收到应答 → 退避重传（1×、2×、4×…），最多 `MaxRetries` 次；随后放弃，等下一个周期 |
| 幂等 | 中心按 `reqId` 去重：重复请求回**缓存的应答**，**不重复递增 revision**、不重复计入限流 |
| 分块发送 | 收到请求后**立即整批发出**（实现期修正：不再逐块延迟 8ms）。典型清单只有 1~7 块，突发很小；丢包由位图重传补齐，不必为每个包插延迟 |
| 分块确认 | 接收方回 `ACKP` 位图；发送方只重发缺失块，最多 5 轮 |
| 传输超时 | 单个 `xferId` 超过 **60s** 未完成 → 双方丢弃上下文；下一周期重新发起 |
| 并发 | 中心最多同时处理 **32** 个传输（LRU 淘汰最旧） |
| 限流 | **按类型区分**：`REG`/`SYNC` 每来源地址 **20 报文/秒**（够 1 秒一个心跳且有冗余）；`PART`/`ACKP` **200 报文/秒**（分块突发远高于请求频率，若与请求共用 20/秒 会把正常分块传输掐死）。超限回 `ERR throttled` + `retryAfter` |
| 位图也验签 | `ACKP` 必须通过签名校验：否则伪造的位图能让中心把（成员清单的）分块发到任意地址 |

### 5.6 幂等与 revision 语义

- `revision` 是中心的**单调递增**计数器，**只在"可分发相关状态真的变化"时 +1**：
  `ip` / `port` / `tcp` / `udp` / `distributable` / `name` 变化，或节点新增、被删除。
- **纯心跳（仅 `lastSeen` 刷新）不递增 revision** —— 否则每个客户端每个心跳都要拉一次快照，白白放大流量。
- `online` 变化（§10.1）是否递增：**递增**，因为客户端界面要显示在线状态。

### 5.7 报文示例

**首次注册（客户端 rev=0）**
```text
→ LT1|REG|{"reqId":"a1b2c3d4","nodeId":"3f2a…","name":"机房A","ip":"203.0.113.10","port":50001,"tcp":true,"udp":true,"distributable":true,"instance":"7d1e…","rev":0,"ts":1789000000,"nonce":"9f8e7d6c","mac":"…"}\n
← LT1|ACK|{"reqId":"a1b2c3d4","rev":138,"changed":true,"reannounceAfter":180,"selfCheck":{"seenIp":"198.51.100.7","seenPort":41234},"nodes":[…],"deleted":[]}\n
```

**稳态心跳（无变化）**
```text
→ LT1|REG|{…,"rev":138,…}\n
← LT1|ACK|{"reqId":"…","rev":138,"changed":false,"reannounceAfter":180}\n      ← 1 个包
```

**回环地址被拒**
```text
← LT1|ERR|{"reqId":"…","code":"loopback","message":"PublicHost 是本机回环地址，不会被分发","retryAfter":0}\n
```

## 6. 地址规则与可分发性

### 6.1 不可分发地址（中心拒绝分发，回 `ERR`）

| 地址 | 判定 | 原因 |
|---|---|---|
| `127.0.0.0/8`、`::1` | 回环 → `loopback` | **其他节点会探测自己的回环**，得到"0.1ms、零丢包"的完美假链路。对测试工具是灾难性误导 |
| `0.0.0.0`、空、`::` | 未指定 → `unspecified` | 无可达语义。（Syncthing 在无 NAT 时用报文源地址兜底；**NAT 场景不成立**，见 §6.3） |
| `169.254.0.0/16`、`fe80::/10` | link-local → `linklocal` | 不可路由 |

### 6.2 其余地址与显式开关

- 私网 `10/8`、`172.16/12`、`192.168/16` 与公网地址：**允许分发**（机房之间可能走内网/VPN）。
- `distributable=false` 的节点：**不进入任何客户端的链路清单**，但仍存在于中心清单里（中心界面可见、标灰）；其状态变化照常递增 `revision`，只是不出现在快照的 `nodes[]` 里。
  典型用途：注册中心那台机器、临时接进来只做排查的机器。
- **中心侧覆盖开关 `centerHidden`**：中心界面每个节点有一个「分发」勾选框，写的是中心的 `centerHidden`，**不是**改对端配置。
  生效规则：`实际分发 = 节点自报的 distributable && !centerHidden`。
  之所以必须这样：节点每次心跳都会重报自己的 `distributable`，若中心直接改对端字段，下一个心跳就被覆盖回去了。用中心侧独立字段才可以"中心想让谁隐身就让谁隐身"，且无需动那台机器的配置。
- 中心界面每个节点显示"分发状态"与原因（正常 / 回环 / 未指定 / 已关分发 / 中心已隐藏）。

### 6.3 `PublicHost` 为什么必须手填（不能用源地址自动推断）

客户端向中心发起的是**出向** UDP，NAT 会给这条流分配一个**临时源端口**，它**不等于**机房入向静态映射的那个端口。因此"中心看到的源地址"通常**不是**别人能探测到你的地址。

- 协议因此**只用源地址做交叉核对**：`ACK.selfCheck` 回显中心看到的 `ip:port`，客户端在设置页与手填值并排显示；两者不一致时给黄色提示"若你的机房做了 NAT 映射，这是正常的；请确认手填值是对外映射的那个端口"。
- 客户端**绝不**用 `selfCheck` 覆盖 `PublicHost`。

## 7. 中心状态与持久化

```text
RegistryState { revision: ulong, nodes: map<nodeId, NodeRecord> }
NodeRecord    { nodeId, name, ip, port, tcp, udp, distributable, centerHidden,
                instanceId, firstSeenUtc, lastSeenUtc, online, authenticated }
```

- `distributable` 来自节点自报；`centerHidden` 是中心侧覆盖（§6.2）；实际分发 = 两者与运算。
- 落盘 `registry.json`（§4.3），原子写；启动时载入；`revision` 继续单调。
- **不做**：按变更打墓碑、每节点 rev、中心间联邦。只维护一份**移除名单**（§9.1）。

## 8. 客户端同步算法

### 8.1 状态机

```text
启动 → 载入 appsettings.json（含上次的注册链路，直接可用）
  └─ Registrar.Enabled ?
       ├─ 否 → 不启动同步（现有行为完全不变）
       └─ 是 → 进入循环：
            立即一次 REG（不等 HeartbeatSeconds）
            每 max(HeartbeatSeconds, ACK.reannounceAfter 的相反数约束) 见 §8.2：
              发 REG(reqId, 本地 rev)
                收到 ACK(changed=false)      → 无操作
                收到 ACK(changed=true)       → 应用快照（§8.3）→ 保存配置文件
                收到 ERR(loopback/…)         → 记录提示，继续心跳
                超时/重传耗尽                 → 标记"中心不可达"，按退避继续（探测不受影响）
```

### 8.2 周期策略

- 下次间隔 = `max(SyncSeconds … 心跳)` 的**两个独立计时器**：
  - **心跳**：每 `HeartbeatSeconds` 发一次 `REG`（保活 + 顺带同步）。
  - **强制同步**：每 `SyncSeconds` 至少发一次 `REG`（即使心跳失败）。
- `ACK.reannounceAfter` **只允许把间隔调短**（下限 `HeartbeatSeconds`）；中心不可用它把客户端拖到远超配置值。

### 8.3 应用快照（关键语义：整体替换）

```text
输入：ACK.nodes（当前全部可分发节点，含中心自身若可分发）、本地 nodeId
1. 过滤掉 nodeId == 本机 nodeId 的条目（自己不进自己的链路）
2. 客户端二次过滤不可用地址（回环/未指定/link-local）→ 计数并在状态栏提示"已跳过 N 个"
3. 目标集合 target = { nodeId → LinkConfig }
     Name      = 节点名
     Host/Port = 节点注册的 ip/port
     Tcp/Udp   = 节点注册的 tcp/udp（即对端宣告的可被探测协议），再「与」本地 LocalDisabled 的反值（§8.5）
     Source    = "registry"，NodeId = 该节点
4. 对 target 中每个 nodeId：本地已存在（同 NodeId）→ 更新变化的字段（保留统计会话不受影响）；
   不存在 → 新增一行
5. 本地存在但 target 中已无、且 Source=registry → **删除该链路**
6. Source=manual 的链路：**完全不动**
7. 有变化才写回 appsettings.json（原子写）
```

- 步骤 5 是 G3（删除传播）的实现：**快照语义天然覆盖"离线期间错过删除"**（§9）。
- 步骤 4 只更新必要字段，避免每次同步都重建 `LinkRow` / 打断统计会话。

### 8.4 与统计/日志的关系

注册链路与本地链路**完全等价**：参与统计、写 CSV（日志文件名仍用链路名，因而按天分目录的布局不变）。链路名来自节点名 → 中心界面对重名会告警（§11.1）。

- **删除一条注册链路后**（同步步骤 5）：已统计到的行、CSV 历史日志**都不受影响**（与现有"删除链路不动数据"的行为一致）；统计表里的该行会保留到点「清除」或重启测试为止。
- 该链路在 `logs\<日期>\` 下的历史 CSV 文件也保留，便于事后追溯。

### 8.5 本地停测（`LocalDisabled`）

- 运维在链路编辑器里把某条**注册链路**的 TCP 与 UDP 都取消勾选 → 界面记录为 `LocalDisabled=true`（并写回配置）。
- 之后每次同步：该链路仍会被生成/保留，但**强制 `Tcp=false, Udp=false`**（即"不主动探测"），中心下发的协议值不再覆盖本地意图。
- 重新勾选任一协议 → `LocalDisabled=false`，恢复按中心值。
- 语义与既有能力一致：**取消勾选 ≠ 删除**（见 `LineTester.md` 的「3.2 新增功能 → 允许两个协议都不勾选」与 `README.md` 的「纯服务端节点 / 单条链路停测」）。

### 8.6 节点身份

- `NodeId` 首次启动生成并写入配置；**配置被复制到另一台机器**会导致两个实例共用同一身份。
- **检测方式（实现期修正）**：不能用"源地址"判断——客户端每次 `REG` 都用新套接字，经 NAT 后**源地址每次都在变**。改为跟踪**进程标识 `instance`**：
  保存最近两个 `instance`；当收到的 `instance` 等于**上一个**值时（即身份在两组进程间来回跳变），判定为两个实例在交替注册。
  干净重启（`instance` 换成全新值）**不算**重复。
- **处置（实现期修正）**：中心**侧只标记** `DuplicateSuspected` 并在节点表标红，**仍然正常返回 ACK**。
  不回 `ERR`：一旦误判就会阻断该节点的正常同步，代价远大于收益。因此错误码表中**没有** `duplicate_nodeid`。
- `instance`（进程随机值）用于识别"对端重启过"：中心可据此把节点从离线标回在线（无需等 TTL）。
- **中心自身的注册**：`ServeAsCenter=true` 且 `Enabled=true`、`CenterHost=127.0.0.1` 时，中心通过回环向自己注册（这样它的记录也进清单，可被其他节点探测）——前提是 `PublicHost` 不是回环地址；若填了回环，它照常被 `loopback` 规则拦下、不分发（这正是"注册中心那台不想被探测"的默认行为）。

### 8.7 客户端实现要点（实现期补充，都是踩过的）

- **只用一个长驻 UDP socket**（不是每请求一个）：分块补发与位图确认都依赖"同一请求的后续帧能回到同一源地址"；
  每请求换 socket 会让源端口每跳一变。
- **同一时刻只允许一个请求在飞**（请求闸门）：心跳循环会立即注册，而界面还有"立即注册"，
  两者并发时两个 receive 会各自抢到对方的回包、再因 `reqId` 不符丢弃 → 表现为**间歇性"中心无应答"**（实测踩过）。
- **不持久化 revision**：进程启动时从 0 开始，中心发现 rev 不同即回全量快照，天然自愈
  （也覆盖中心清单被重置/回退的情况）。
- 公开的"立即注册/立即同步"接口**不抛异常**，失败只反映在状态里（界面不该看到原始异常）。
- 对端把请求**原样回显**时，直接判定"该地址不是注册中心"，而不是等到超时（规格 §12）。

### 8.8 协议日志

- 每次注册/同步的结果与协议层错误，追加写入 `logs\<日期>\registry.log`（复用按天分目录的布局）。
- 内容：时间、方向、`reqId`、`rev`、结果（ok / ERR code / 超时 / 分块重传次数）。
- **不记录密钥或 `mac`**（避免把认证材料落盘）。
- 作用：现场"为什么没同步上"不用抓包就能看（例如 `ERR auth`、`unsupported`、分块反复重传）。

## 9. 删除传播

### 9.1 删除必须持久（实现期修正：早期设计漏了这一点）

**只把节点从清单里删掉是不够的**：被删的节点**还在运行、还会继续心跳**，下一拍就通过 `REG`
把自己 upsert 回来了——"在测试中心删除"就退化成一次性动作，而不是权威决定。

因此中心维护一份**持久化的移除名单** `removedNodeIds`：

- `删除节点` = 从清单移除 **+ 记入移除名单** + `rev++`；
- 移除名单里的 `nodeId` 再注册时回 `ERR removed`，**不会被心跳加回来**；
- 需要恢复时由中心显式恢复（从名单移除），该节点随下一次心跳重新出现；
- 清单里未知的 `nodeId` 也可以直接移除（等于**预先封禁**，用于还没接进来的机器）。

这是"墓碑"思想的最小形态：不按变更打墓碑、也不需要每节点 rev，只需一份"禁止回归"的名单。

### 9.2 传播为什么用全量快照（而不是差值）

**早期设计**用"差值 + 墓碑 + 每节点 rev"，理由是"离线节点会复活已删链路"。改用**全量快照语义**后：

- 客户端每次拿到的是**当前可分发清单的完整快照**，本地注册链路**整体替换** → 离线过的节点
  一次同步就拿到"不含被删节点"的快照，该链路消失。
- 流量代价可控：无变化时 `changed=false`，稳态每个心跳**只有 1 个包**；仅在变更后才有一次（可能分块的）快照。
- `deleted[]` 字段保留占位，v1 恒为空——**节点级删除靠 `removedNodeIds` + 快照缺席双重保证**。

**快照语义下的一个反例**：如果客户端自己**手工**构造了一条与某节点同 `NodeId` 的链路，
它会在下次同步被清理掉（因为它是 `Source=registry`）。手工链路请用 `Source=manual`（界面新增的行默认就是 manual）。

## 10. 离线与失败处理

### 10.1 节点离线（中心侧）

- `lastSeenUtc` 超过 **TTL = 3 × HeartbeatSeconds**（默认 180s）→ `online=false`。
- **只标记、不删除**：节点抖动或临时断网不应让它从所有人的清单里消失。revision 递增（界面要显示状态）。
- 中心界面显示"在线 / 离线（已 N 分钟）"。
- **判活必须有人触发**（实现期补充）：中心在组装 `ACK` 时（即每个 `REG`/`SYNC`）调用一次
  `RefreshOnlineState()`——这是唯一"总会有人来"的位置；界面每次刷新中心表时也调用一次，
  这样即使长时间没有任何客户端，表里的在线状态也不会停在旧值。

### 10.2 中心不可达（客户端侧）

- 探测**完全不受影响**（用的是上次同步到的清单）。
- 状态栏提示"注册中心不可达（已 N 分钟，退避中）"。
- 退避：`RetryMs` 起步，指数增长到 **30 × RetryMs** 封顶，恢复成功后退回基础值。

### 10.3 时钟偏差

- `ts` 校验容忍 ±300s；超出回 `ERR auth`。状态栏提示"与本机时间偏差过大"。

### 10.4 密钥错误 / 未配置

- 未配置 `Secret`：仍可注册，但中心标记 `unauthenticated` 且界面标红；客户端状态栏提示"未配置密钥，任何人可改清单"。
- 密钥错：`ERR auth` + 指数退避，**不刷屏**；提示核对密钥。

### 11.1.1 运行期行为（实现期补充）

- **新链路无需重启测试**：探测循环每轮读取链路快照，中心同步到新链路后立刻开始探测。
- **手工改动同样即时生效**（实现期修正）：协议勾选（TCP/UDP）**立刻**作用到运行中的链路
  （它只会收窄发包范围，不会把包打到半截的地址上）；主机/端口/名称改动约 **1 秒防抖**后生效
  （端口是一格一格敲进去的，逐字符生效会真的往 9 端口发包）。
  之前"改完必须重启才生效"的口径导致现场出现"界面写着不发包、包却照发"，统计跟着失真。
- **注册链路只读**：链路配置页的名称/主机/端口禁止本地编辑（改了也会被下一个同步覆盖），
  删除按钮会拦下并给出两条正确出路（中心侧移除 / 本地停测）。
- **地址输入是标准 IPv4 四段式**，端口/周期只收半角数字：现场出现过"把 IP 敲进端口框"，
  报错却是"必须是 1~65535"，无从下手。
- 中心判活由中心在组装 `ACK` 时调用一次 `RefreshOnlineState()` 完成——它是唯一"总会有人来"的位置。

### 11.2 「链路配置」页联动

- 新增「**来源**」列：`本地` / `注册中心`。
- 注册链路：名称/主机/端口**只读**（禁止本地改），删除按钮提示
  "该链路来自注册中心，删除请在注册中心操作；本地停测请把 TCP 与 UDP 都取消勾选"。
- 本地停测的注册链路在「校验」列显示"本地已停测（不会被同步覆盖）"；
  正常注册链路在该列显示"来自注册中心（自动维护）"（这一列同时承担备注作用）。

### 11.3 状态栏

- 未启用注册：不显示相关提示（与现状一致）。
- 启用后：`注册中心 203.0.113.1:50000 · rev 138 · 节点 6 · 12:03 同步` 或
  `⚠ 注册中心不可达（已 4 分钟，退避中）`。
- 颜色：注册告警用橙色（不是红色）——它代表"同步有问题"，而红色保留给"测试/日志本身出错"。

## 12. 兼容矩阵

| 本端 | 对端 | 结果 |
|---|---|---|
| 新（含注册） | 新 | 注册/同步正常 |
| 新发 `LT1|` → **老**节点 | 老节点把它当探测包**原样回显**（老服务端是纯回显） | 发起方收到"自己的请求被回显" → 判定 `unsupported`，状态栏提示"该地址不是注册中心"，**不重试风暴**、**不影响探测** |
| 新发 `LT1|` → **新但非中心**节点（实现期补充） | 该节点在收包分流处明确回 `ERR unsupported`（比静默回显更容易现场定位"中心地址填成了普通节点"） | 收到终态错误，同样**不重传**，原因直接显示在状态区 |
| 新探测 → 老节点 | 与现在一致（老服务端原样回显） | 正常 |
| 老探测 → **新**节点 | 新服务端判定非 `LT1|` → 走原探测回显路径 | 正常（老客户端逐字节比对通过） |
| 老客户端 | 新中心 | 老客户端不发注册消息 → 中心的清单里没有它（除非手工登记），其余节点测不到它；**不报错、不误判** |

> 兼容性由"前缀分流"保证：只有以 `LT1|` 开头的报文才进入注册路径，
> 探测回显路径一个字节都没改（T14 逐行复核）。

## 13. 验收标准

| 编号 | 可观测验收 |
|---|---|
| A1 | 三个节点只需各填「自己 + 中心」→ 每个节点自动出现另外 2 条链路；协议与对端注册值一致 |
| A2 | 中心删除节点 B → A 与 C 的 B 链路在 ≤ `SyncSeconds`（默认 300s，现场可调 60s）内消失 |
| A3 | A 在删除期间离线，A 重新上线 → A 的 B 链路**也消失** |
| A4 | 关掉中心进程 → A/C 的探测与统计**不中断**，状态栏提示不可达；中心恢复后自动续上 |
| A5 | A 手工加的链路在任意次同步后**依然存在**，内容不变 |
| A6 | A 把某条注册链路 TCP/UDP 都取消勾选 → 之后每次同步仍保持"不发包"（本地停测不被覆盖） |
| A7 | 把某节点 `PublicHost` 设为 `127.0.0.1` → **该节点的注册被中心拒绝**（`ERR loopback`），其他节点不会出现该链路；节点自己的「注册中心」页状态区同时标红提示"回环地址不可分发"（地址填错在**发起端**就能看见，不用去中心翻表） |
| A8 | 大快照能正确分块传输并被位图确认补齐：**只声明收到第 0 块 → 中心只补发其余块**；全部确认后不再补发；未验签的位图被忽略（用位图层面的"故意丢包"替代 UDP 代理，确定性且不打折扣） |
| A9 | 老版本节点混跑：`LT1|` 打到老服务端 → 本方标记 `unsupported` 且**不产生任何丢包记录** |
| A11 | 某节点关掉 `AdvertiseTcp`（只宣告 UDP）→ 其他节点为它生成的链路是 **`Udp=true, Tcp=false`**，实时统计里只有 UDP 行，**不出现 TCP 丢包** |
| A12 | 中心对某节点勾掉「分发」（`centerHidden`）→ 其他节点该链路消失；该节点再次心跳**不会**把它顶回来；取消勾选后恢复 |
| A13 | 同步失败/密钥错误/分块重传，都能在 `logs\<日期>\registry.log` 里看到原因，且日志中**不含密钥与 mac** |
| A10 | 自检全绿；新增断言覆盖：帧编解码、HMAC/防重放、分块与位图、快照应用（增/改/删/跳过自己/跳过不可用地址/保留 LocalDisabled/不动 manual）、中心 TTL 与 rev 语义 |

## 16. 风险与未决

| 风险 | 影响 | 缓解 |
|---|---|---|
| 中心单点 | 只影响新增/删除可见性 | G4 离线可用；中心可选任意一台，切换只需改各节点的 `CenterHost` |
| UDP 分块被中间设备限速/丢包 | 首次全量同步变慢 | 块间隔 8ms + 位图重传 + 60s 超时重来；稳态只需 1 包 |
| `PublicHost` 填错 | 其他节点全部测不通 | `selfCheck` 交叉核对提示；中心界面显示每个节点的地址，删错/填错一眼可见 |
| 密钥硬编码/弱密钥 | 可被伪造注册或恶意删除 | 未配置密钥时中心界面标红；HMAC 不上线密钥；文档要求定期轮换 |
| 节点名重复 | 界面与统计里难以区分两个同名节点 | 中心节点表标黄告警（并排显示各自的 `ip:port`）；日志文件名仍含 `ip:port`，不会互相覆盖 |
| **未决**：`HeartbeatSeconds`/`SyncSeconds` 现场取值 | 变更可见延迟 vs 流量 | 默认 60/300，现场可调（建议现场 60/60） |

## 17. ADR 信号

- **涉及的持久架构面**：新增线协议（端口复用与帧格式）、新增配置段与字段（`Registrar`、`Links.Source/NodeId/LocalDisabled`）、新增角色（注册中心）、新增持久化文件（`registry.json`）、兼容边界（老版本混跑）。
- **真实备选**：① 外部注册中心（Consul/etcd）② 复用飞书多维表/web SQL 当清单 ③ 显式链路矩阵（部分网格）。
- **未选原因**：① 需要第二个端口映射，与"只映射一个端口"冲突；② 依赖外网与第三方可用性，且与"同端口协议区分"要求不符；③ 把手工工作量从客户端搬到中心，未解决 N² 问题。
- **待办**：实现并线上验证后，用 `recording-architecture-decisions` 落一条 ADR，并把本文件升为"已实现"状态。
