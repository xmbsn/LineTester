## 一、需求与最终形态

现场要求：在「链路实时统计」页勾选一条或多条链路，把它们的测试结果画成曲线——
横轴时间、纵轴 RTT(ms)，鼠标移上去显示当前时刻**所有**曲线的取值，曲线名 = **链路名称 + 协议名称**；
参考 GitHub 上的同类项目，界面要专业美观。

**后续追加的两条要求（都改变了设计）**：
- 曲线要**展现会话的所有数据**（不是滚动窗口）→ 横轴改为"会话全程"；
- **曲线缩放功能需要** → 加了滚轮锚点缩放 / 拖拽平移 / 双击全览。

最终形态：
- 「链路实时统计」表最左侧新增**「曲线」勾选列**；勾选 = 显示，**数据与勾选无关、一直都在记**。
- 新标签页 **「RTT 曲线」**：工具条（全览 + 当前范围文案 + 操作提示）+ 曲线 + 可点击图例。
- 纵轴**只跟当前可见数据的最大值**自适应；阈值在刻度内画橙色虚线，超出刻度只在角落提示。
- 横轴 = 会话全程；长会话按**像素列聚合**（每列最小/最大包络 + 均值折线），数据一条不丢。
- 悬停：竖线吸附到最近采样时刻，提示框列出同一时刻所有曲线的值（丢包显示"丢包"），
  时刻精确到毫秒可与 CSV 对齐，并在线上标出取值点。
- 丢包：曲线断开 + 底部淡红竖条 + 断口处红色空心点（高度取上一次成功的 RTT）。

## 三、关键设计决策（以及为什么）

| 决策 | 理由 |
| --- | --- |
| **自绘**（`FrameworkElement`/`Control` + 双 `DrawingVisual`） | 本项目零 NuGet 依赖（NuGet 不可达、自检宿主靠这条能跑），LiveCharts/OxyPlot/MvvmChart 一律不能用。照搬的是它们的**交互模式**，不是代码 |
| 双图层（曲线层 / 悬停交互层） | 鼠标每动一下只重画交互层；否则长会话下每次移动都要重算几万个点 |
| 曲线**单独**存会话历史（`ChartHistory`），不复用「实时RTT明细」 | 明细表只留最后 2000 条，现场 7 链路 × 3 协议 = 每秒 21 条 → 只够约 95 秒，画不出一个会话 |
| 横轴默认全程 + 像素列聚合 | 现场要先看"整段时间什么样"；聚合而不是隔点抽样，尖刺不会被抽掉 |
| 缩放**以鼠标位置为锚点** | 以区间中心缩放会让"正在盯着看的那一段"跑掉，是图表工具里最常见的失手 |
| 配色用 Okabe-Ito 色盲友好色板 | 现场 21 条曲线，颜色必须一眼分得开；这不是审美偏好 |
| 记录与勾选**解耦** | 勾选只是显示开关；否则晚勾选的链路看不到前面的数据 |

## 四、本轮踩到的三个真实缺陷（都是我自己引入的）

### 1. 曲线整条看不见（`382dcf7` 内修掉）

按"像素列"连线时把**空像素列当成了断口**——会话刚开始时采样点（1 秒 1 个）比像素列稀疏得多，
每个点都单独成为一个"单点图形"，而单点图形画不出任何东西 → 整条曲线是空的（肉眼看只会以为"没数据"）。
**改为"空列不断口，只在真正的时间断档处断开"**。

### 2. 纵轴看起来是个固定值（`4585fb1`，现场反馈）

把 `WarningRttMs`（默认 300ms）的告警阈值也并进了 Y 轴上界 → 数据只有 20ms 时轴顶也被顶到 400ms，
曲线全挤在底部，"自适应"名存实亡。
**改为上界只跟可见数据最大值走**；阈值落在刻度内才画虚线，超出就在角落写"峰值未到阈值"——
不为画阈值线牺牲数据可读性。

### 3. 晚勾选的链路没有前面的数据（`3a00eda`，现场反馈）

`ChartHistory.Add` 只写给**已勾选**的曲线 → 没勾选的链路连采样都不存，勾选那一刻之前的整段是空的。
**改为记录与勾选解耦**：见到哪条链路就记哪条；`Selected` 退化为纯显示开关。
界面同步说清"没曲线 ≠ 没数据"。

## 五、没有视觉模型时，怎么保证"图是对的"

本机没有可用的视觉能力（`read_image` 当前模型不支持图像输入、`modlens` 未配置 vision provider），
所以"画出来没有"只能靠证据链，分三层：

1. **纯计算**（`src/ChartMath.cs`，不引用 WPF）：刻度取整、屏幕↔时间换算、悬停吸附、像素列聚合、
   缩放锚点（缩放前后鼠标指着的时刻位置不变）、平移夹取、最小缩放粒度。**约 60 条断言。**
2. **像素级渲染断言**：把控件渲染成 `RenderTargetBitmap`，**按配色去数像素**——
   数得到曲线色、网格色、阈值标注色、丢包红点色，才说明真的画到了画面上。
   - 两个坑：`RenderTargetBitmap` 是**预乘 alpha**（不还原原色就会把抗锯齿的细线误判成"没画"）；
     窗口不 `Show()` 时**不跑布局**（控件尺寸为 0，缩放/悬停会静默跳过）。
   - 这条断言抓出了上面第 1 个缺陷；也是第 2 个缺陷的回归守卫
     （23ms 的曲线必须落在绘图区上半部分，而不是贴在底部 30 像素处）。
3. **真实窗口端到端**：勾选出图、勾选前后数据都在、滚轮缩放（真实 `MouseWheel` 事件）、
   全览复位、图例隐藏/显示、取消勾选撤图而历史保留。

**"好不好看"这一关只能人过**：`--render-ui` 会把各页渲染成 PNG（`ui_1.png` 就是曲线页），
由现场肉眼确认；模型看不了图，这一点在 README 里也写明了。
